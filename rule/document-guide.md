# 文档指南

> **目的**:文档写给没有对话上下文的读者;结构是第一可读性——先立骨架,再填内容。

> **对象**:为用户产出的一切 Markdown 文档(设计稿、报告、对照分析、方案)。

## 铁律

1. **先骨架后内容**:全文一条主线,目录与主线一致——读者凭目录能预判每节内容。动笔前先定骨架和每章模板。
2. **每章同构**:同一文档中各章形状相同。例:驱动问题 → 事实/后果表 → 可执行结论;或 问题 → 候选(含利弊)→ 定案 → 为什么。读者建立一次阅读习惯即可通读全文。
3. **自持**:文档之间不互相引用("详见 XX.md"禁止);需要别处的结论就地内联。链接只用于源码等外部证据。
4. **事实必须带后果**:每条事实后跟一句"这意味着什么 / 会在哪坏"。禁止用形容词代替证据("最完善"、"教科书"、"轻量")。
5. **句子带主语**:对话中的口语压缩("能不能做")不进文档;进文档必须是完整句。
6. **坐标系先行**:涉及多维度对比时,先声明分类体系本身(如"问题空间 vs 解空间"),再按体系展开。

## 概览章模板

长文档以概览开头,回答四问:**目标**(为谁、验收口径)→ **为什么难** → **是什么**(一句话形态 + 核心模型)→ **做什么**(交付物、路线、既定决策)。
